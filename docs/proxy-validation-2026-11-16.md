# 短效代理修复与验证记录

日期：2026-11-16。按离线复现、原代码真网基线、正式修复、离线回归、真网复测的顺序执行。供应商配置仍由本地 `.env` 加载，未修改凭证、采购参数或默认并发/超时配置。

## 离线依据与修复范围

修改源码前，已有 16 个证据用例全部复现审查发现。正式回归位于 `tests/unit/test_proxy_regressions.py`，断言修复后的正确行为，并包含真实线程交错、真实 requests 响应体异常包装及可控时钟测试。

| 优先级 | 修复 | 验证依据 |
|---|---|---|
| P1 | 后台续期仅安装批次，业务领取才计占用与服役 | 所有真实请求归还后占用为零；续期不增加服役数量 |
| P1 | 池空抛出 `ProxyUnavailableError`，禁止隐式直连 | always / auto 代理态下空池不调用业务 Session |
| P1 | 固定首页总量，空末页及总量不一致进入补漏 | 首页 200、末页 0 不再输出 total=0；保留缺失信息 |
| P1 | 删除三轮失败后强行采用最后一批的逻辑 | 双源全部预筛失败时没有黑名单 IP 被发放 |
| P2 | TTL 从采购请求开始计算，扣除回源和预筛耗时 | 8 秒预筛不延长30秒租期；入池前过期的批次被拒绝 |
| P2 | 绝对预算传递到锁等待、预筛和传输重试 | 超预算不继续发满11次请求，锁等待可超时退出 |
| P2 | 路由请求记录代际，迟到结果不能完成新探测或污染直连状态 | 真实线程复现旧直连成功晚于新探测发起的交错 |
| P2 | 读取响应体的超时识别为软失败；404/5xx不直接淘汰出口 | 使用 requests.Response.content 触发实际异常包装 |
| P2 | 补漏不把正确已收集页面判为坏出口 | 正确的重复页面不触发 evict |
| P2 | 全量任务使用独立客户端并先关闭、后记账 | 两个各1请求的任务分别记1、1，关闭后才生成账本 |
| P2 | 限制代理管理器数量，保留在途响应体对应连接 | 100个不同代理仍受缓存上限约束；读取中管理器被保护 |
| P2 | 关闭客户端等待后台续期结束，禁止关闭后新批次入池 | 用事件控制在途续期与close交错 |
| 配置 | 校验非正超时、负余量、非有限退避值；实现随机jitter | 参数化配置测试与可注入随机采样 |

为避免常驻客户端历史集合无限增长，每个唯一IP集合上限8192，超过时 `history_truncated=true`，唯一数变为下界。交付量和采购次数仍完整累计。全量快照客户端任务结束释放，因此每次任务账本不再包含前一任务的累计统计。

`EM_PROXY_NUM` 仍是本地保留数量，不能代替供应商采购 URL 的数量参数；本轮通过文档明确这一点，未盲目调小它。

## 真网基线与复测

两轮均使用原 `.env`，仅测试进程覆盖为 always、max_retries=2。双并发，每页100条，固定代码排序，每组之间等待2秒，采购最多12次，约95秒停止新采购。测试拦截无显式代理的业务请求，并独立记录拦截次数，以免验证过程意外走其他出口。

| 指标 | 原代码基线 | 修复后复测 |
|---|---:|---:|
| 业务调用数 | 44 | 64 |
| 成功调用 | 36 | 62 |
| 失败调用 | 8 | 2 |
| 业务 HTTP 尝试（含重试） | 66 | 75 |
| 失败 HTTP 尝试 | 30 | 13 |
| 真实采购 API 调用 | 7 | 6 |
| 交付 IP 数 | 35 | 30 |
| 调用耗时 P50（排序后中间值，含失败） | 0.734s | 0.404s |
| 调用耗时 P95（最近秩，含失败） | 6.653s | 2.978s |
| 无显式代理业务请求 / 拦截 | 0 / 0 | 0 / 0 |
| 最终在飞占用 | 0 | 0 |

修复后最后两次调用在测试窗口结束附近发起，采购随后被测试器的95秒上限拒绝，最终返回 `ProxyUnavailableError`。不能将其描述为整轮64次全成功，也不能将模拟的空采购记作实际供应商失败：本轮真实API调用6次，池内fetch_calls=9包含3次被测试器拒绝的回源调用。

修复后 at=59.53s 样本观测到 renewing=true，at=61.96s 已完成；两者在飞占用均为0。原代码基线没有观测到后台续期，因此基线占用为0不能否定离线复现的计数泄漏。

两轮来自不同时间的随机代理，源使用比例也不同。这是回归与运行表现的证据，不是交替随机A/B，不能把吞吐差异全部归因于修复，也不能据此认定某个超时/批量已最优。

原始脱敏记录位于本地忽略目录：`.arts/proxy-audit/baseline.json`、`repaired.json`。脚本为同目录的 `validate_live.py`。

## 最终检查与限制

- 正式测试：1060 passed（原1033项，新增27项），包括分层和文档守卫。
- Ruff检查、格式检查、mypy strict（130个源码文件）、git diff --check通过。
- Python3.13.12，requests2.34.2，urllib3 2.8.0；未执行其他Python版本矩阵。
- 同步 requests 的DNS解析、持续滴流响应及在途线程不能被硬取消。预算用于限制等待、网络超时和后续尝试，不承诺严格墙钟截止；close也需要等待已发出的后台请求退出。
- 全量任务最终不完整时仍遵循原有返回并告警的契约；应检查 `len(items)==total`，尚未引入新的strict API。
- 全量任务改为独立客户端，减少统计串扰并保证资源释放，但连续任务不会复用上一个全量任务的温热连接。单页接口仍使用缓存客户端。
- 真网样本覆盖数个30秒周期，不能替代数小时RSS/FD稳定性测试或交易时段负载测试。
- 预筛目标仍为A股列表，对其他host的健康检查、动态超时按端点分桶、全局出口并发预算和CI多版本矩阵属于后续改进，未与本轮确定性修复混在一起。
