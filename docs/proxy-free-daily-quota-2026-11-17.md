# 免费套餐每日额度接入

用户确认免费源每天1000个IP，0:00:00更新。本轮按北京时间（UTC+8）处理，实际接口查询确认：免费套餐num=1000、use=0、valid=true、enddate=2026/11/18 0:00:00；收费次数套餐num=8000、use=7155、可用845。流量套餐不参与IP次数计算。

本轮只查询余额接口，没有提取或使用代理；进程新增使用上限保持0，没有自动启动盘中或压力测试。当前实际时间已为2026-11-17，北京时间日桶为2026-11-17。查询密钥没有写入本文或版本控制。

## 规则

- 新增`EM_PROXY_USAGE_FREE_DAILY_LIMIT`，默认0保持旧模式；本地.env设为1000，既有FREE_LIMIT=0、PAID_LIMIT=812及MAX_NEW=0不变。
- 启用日模式后，免费准入依据日桶而不是静态FREE_LIMIT；账户累计reserved仍保留。免费与收费各有远程限制，免费用量不扣收费远程限制。
- 每次新日期首次检查绕过前日缓存，查询到有效免费套餐且到期时间准确指向次日北京时间0点，才建当日记录。午夜本身不自动允许任何新IP；缺失/失效/歧义/旧套餐则拒绝免费新使用，原收费路径继续可用。
- 同一天的远程更新只能收紧，扣减延迟或反复刷新不恢复已预占。免费套餐正确但未返回收费套餐时，免费仍可更新；收费保留本地和已有远程限制。
- 日数据、使用身份和事件在同一SQLite事务内更新，跨线程/进程共享；不删除前日记录、不重置进程限额。跨午夜仍未过期的同免费租期再使用，保守记新一天一次预占，事件保存quota_day。
- 持久化新增free_daily_limits、free_daily_uses，usage_attempts增加quota_day。既有remote_limits加入scope并从旧账号总预占基准迁到收费预占基准，保持迁移前收费可用量；再次启动不会重复迁移。

日额度启用后，`account.free.initial=0`是旧配置初始值，`account.free.remaining=1000`来自当天有效免费套餐，两者并不矛盾。准确日信息查看`free_daily`字段。收费仍为本地805、远程845，取保守限制；日重置不会将其放宽。

## 验证

新增28项离线测试，覆盖免费/收费隔离、午夜前后、跨午夜租期、旧接口缓存、日期回拨、跨午夜查询、重启、日限额竞争、账户迁移、暂停上限0、事务回滚、免费套餐缺失或非法、仅免费套餐及配置加载。

当前工作区完整测试1311项通过（18.26秒），严格mypy检查134个源码文件通过；相关文件Ruff和格式检查通过。工作区还含此前其他未提交的网络策略/固定代理改动，本次保留这些改动，不将其宣称为本轮新增功能，也未提交Git。

对真实本地SQLite先做备份再校验：免费当日1000、已用0、预占0；收费累计预占7、本地剩805；远程收费845；进程limit=0、reserved=0。前后accounts.reserved完全相同，确认没有消耗任何代理使用额度。

原始脱敏校验：`.arts/proxy-audit/daily-balance-verification.json`。

## 限制

供应商是否将跨午夜旧租期使用计入新一天尚未逐笔确认，本地采取保守预占。当前套餐到期字段恰好为次日0点；若供应商以后改变字段语义或格式，免费路径会拒绝新使用而不是猜测。失败刷新时当天已有保守上限可以继续约束；新一天无有效记录则额度为0。
