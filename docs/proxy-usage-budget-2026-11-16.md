# 首次使用额度保护：实现与离线验收

## 本轮范围

完成用户要求的三项：预筛与业务统一使用预占、首次使用前限制账户与进程预算、配置免费0/收费初始812，并执行离线测试。没有请求供应商API，没有访问行情站点，没有消耗真实IP额度。

用户确认的计费规则是type=0免费、type=2收费，提取不计使用，使用IP才消耗。本实现按此建立保守的本地预占模型，不把它冒充供应商扣费查询。

## 当前配置

本地 `.env` 增加：

```dotenv
EM_PROXY_USAGE_DB=/home/know/projects/emshare/.arts/proxy-usage.sqlite3
EM_PROXY_USAGE_FREE_LIMIT=0
EM_PROXY_USAGE_PAID_LIMIT=812
EM_PROXY_USAGE_MAX_NEW=20
```

免费0表示跳过该来源提取和预筛；收费812是建立账本时的用户确认余额起点。20是本次选择的保守进程级新增使用上限，覆盖该进程的全部客户端和预筛线程。未来重启会建立新的进程上限，但不会恢复账户已预占额度。进程内更换配置或清理HTTP客户端缓存不能重置使用预算。

已在禁用socket连接的进程中读取实际配置并初始化账本，确认：免费剩余0、收费本地剩余812、账户预占0、进程预占0、进程上限20。此初始化只写本地SQLite，不发网络请求。

这些设置写入用户本地.env，模板保持空值，避免把本账号余额套用到其他用户。未启用时保持原行为；启用时必须同时填写数据库路径、免费初始额度、收费初始额度，局部或负数配置直接报错。

## 使用路径

1. 从供应商提取批次后，为本地保留的代理登记来源与租期；不预占使用额度。
2. 同一来源、同一规范化IP:端口、未过期租期的再次交付沿用原租期标识，不延长租期或重新预占。代理认证信息、URL scheme不用于区分同一出口身份。
3. 预筛即将调用探测回调之前，或者业务真正调用Session.get之前，均进入 `ProxyPool.reserve_usage` → `ProxyUsage.reserve`。
4. SQLite事务同时检查账户余额和进程新增使用预算；首次使用原子增加一次预占。预筛与业务共享同一预占，同租期重试不重复预占。每阶段的使用数和尝试数独立记录。
5. 并发额度竞争时以事务内检查为最终依据。额度不足不发网络请求，不记黑名单、不伪装成连接失败。部分预筛超额只跳过未获许可的出口，已许可的好出口仍可服务。
6. 失败、超时或协议拒绝不自动退款。进程崩溃或预占后发送前失败也保留预占，这是保守保护而非精确扣费。
7. 账户剩余降至0后，同租期已预占代理仍可复用；不能使用新的代理。来源用完时可转向另一有额度来源，所有预算耗尽抛 `ProxyQuotaExceededError`，不走网络重试或隐式直连。

来源解析只支持已确认的携趣api.xiequ.cn、单一uid、type=0/2。启用额度保护时，无法识别的来源、重复歧义type或缺失租期信息均拒绝使用。一个预算管理器只对应一个账号。

## 持久化与并发

`src/em/core/usage.py` 使用SQLite即时事务，账户额度、首次使用标记、阶段计数和进程预算在同一事务内更新。事务失败全部回滚，预占存储失败则不发送业务请求。数据库锁等待服从可用外层预算，最长默认10秒；不会在存储失败后静默绕过控制。

应用装配按同一绝对数据库路径共享管理器，覆盖普通缓存客户端和独立全市场快照客户端；SQLite文件同时支持多进程共享账户限制。库不创建永久数据库连接，每次事务后关闭连接。

数据库存储账号和代理身份哈希及随机租期标识，不保存uid明文、vkey、完整供应商URL、代理用户名/密码或IP明文。过期租期会在后续登记时清理，累计使用计数保留。数据库不是供应商账户，不会同步外部程序的消费。

初始额度与已存在账本冲突时报错，避免把“后台新的剩余余额”错当作可以重新开始的总额度。不得删除、换账本路径或手动篡改记录来恢复预算；真正需要重新对账时必须明确校准时间与未结束租期。

## 观测口径

- `ips_returned` / 日志“提取”：解析交付条数，不代表实际使用。
- `usage.account.<free|paid>.reserved`：本地累计首次使用预占租期数。
- `remaining`：初始本地额度减累计预占，不是实时后台余额。
- `prefilter_used` / `business_used`：各阶段使用过的租期数量，可重叠，不能相加当总消耗。
- `prefilter_attempts` / `business_attempts`：各阶段已授权尝试数量，含失败。
- `usage.run.reserved`：当前进程新增的预占数。已在前一进程预占且仍有效的同一租期复用，不新增此计数。
- `usage_prefilter_denied` / `usage_filtered`：额度拦截次数，区别于TTL过滤、出口失败。
- `usage_account_snapshot`：每次全市场账本追加的账户累计快照，不能跨行相加。传统报表继续汇总交付量，显示标签由“采购”改为“提取”。

## 离线验证

`tests/unit/test_proxy_usage.py` 覆盖38项用例，测试进程禁止socket连接，所有业务/提取请求使用假Session或回调。跨进程测试只访问临时SQLite，不请求网络。

覆盖包括：提取和领取不预占、预筛和业务去重、免费0跳收费、全0不请求、48并发重复使用只占1个、24不同出口竞争不超过3个、部分预筛被拒不拉黑、额度0复用已预占出口、连接/协议/探测失败不退款、跨客户端同租期去重、新租期重新计数、来源分开计数、重启保留余额、初始额度冲突拒绝、进程预算跨源合计、来源或租期未知拒绝、坏库拒绝、敏感信息不落盘、缓存重置不恢复预算、配置校验、账户快照不混入交付量、两个独立Python进程竞争共享3个额度最多成功3个，以及事务中途失败回滚。

最终全套1114项通过（此前1076项，加本轮38项），耗时14.72秒。Ruff、格式、严格mypy（131个源码文件）及差异检查全部通过。

## 限制

本地身份暂按来源+IP:端口+有效租期计量，供应商是否按纯IP、跨租期或不同失败阶段计费仍未逐笔核实。跨来源相同地址按不同来源保守预占；不同认证值的同地址同来源视为同一出口。改变这些身份规则需先与后台对账。

在预占后、实际发出请求前失败时可能多预占；本实现选择不退款。反过来，其他程序不用同一账本直接消费供应商余额，本控制也无法知晓。因此不能声明其数值等于供应商扣费，或能防止所有外部账户超额。

本轮没有真网对账、没有自动运行后续测试。收费余额812只是用户给定起点；下次真实测试应先确认后台余额及时间窗口，并使用小额进程上限。

已接入账户查询接口：读取响应中的“次数套餐”，用 `num-use` 得到账号级实时剩余；“流量套餐”不参与IP次数额度。实时剩余与本地账本余额取较小值。接口不可达、格式错误或字段非法时保留本地余额，不自动放宽；查询凭证不写入日志或SQLite。
