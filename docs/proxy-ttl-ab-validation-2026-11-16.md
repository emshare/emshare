# 剩余 TTL 派发与复用：离线复现及真网 A/B

## 结论与范围

已完成用户指定的两步：离线验证临期派发/软失败复用边界，并根据复现结果执行隔离候选策略的真网对照。

当前逻辑只验证代理在领取瞬间尚未硬到期，没有要求剩余寿命覆盖本次请求预算。离线确认在代理年龄25.756秒、本地27秒硬到期时，仍可派发连接与读取预算合计6秒的请求；一次读取超时后也可继续复用临期IP。

候选B把领取和hold的资格改为：

`本地剩余有效期 > 本次连接超时 + 本次读取超时`

预算沿用当前动态超时、首次使用连接超时、端点read_timeout提示和上层剩余deadline，不额外改动其他参数。未达门槛的IP不拉黑，不增加失败次数；较年轻备用IP优先满足条件，无符合条件的出口时沿用原回源流程。

本轮没有修改正式源码、默认配置或.env，候选仅在 `.arts/proxy-audit/ttl_candidate.py` 中，通过独立实验客户端启用。结果支持后续正式实现该约束，但样本不足以把观察到的性能变化归因全部归于TTL策略，也不据此更改所有接口的默认行为。

## 离线复现

执行：

```bash
EM_ENV_FILE=none PYTHONPATH=src:.arts/proxy-audit .venv/bin/pytest -q .arts/proxy-audit/test_ttl_boundary.py
```

11项用例通过，包含原逻辑证据与候选正确性断言：

- 25.756秒领取：A仍发旧IP；B使用新批次，旧IP不被记黑名单。
- 20.9秒请求，读取超时消耗3秒：A在退避后复用旧IP；B拒绝hold并换符合预算的IP。
- 临期但上层剩余预算更短：B可复用旧IP，不强制采购。
- 生命周期充分时：B保留正常同IP软失败重试。
- 无新代理时：B抛出ProxyUnavailableError，既不隐式直连，也不将临期IP判死。
- 池中存在年轻备用IP：B直接取备用，不额外采购。
- read_timeout端点提示只作用于本次调用，后续恢复。
- 老IP仍有其他在途请求时：换批不破坏原请求占用，release后归零。
- 供应商重复返回同一临期IP：B不重置其租期，也不发出业务请求。

最后一项同时暴露候选实现的成本限制：回源仍可能重复采购相同临期IP，直至请求重试耗尽。它不会延长旧租期，但正式实现前应补充回源合并、重复交付冷却/拒绝的设计和验证。

## 真网实验设计

- 顺序：A/B/B/A，B/A/A/B；A为现有策略，B为隔离候选。每组使用新客户端，结束关闭，不跨组保留池或动态超时历史。
- 每组固定24次业务调用、双并发、100条/页、代码排序；总计192次，双方各96次。
- 每组先做2次冷启动请求，再等池中最早有效IP年龄约25.756秒时发出2次临期请求，之后完成20次调用，组内请求对之间间隔2秒。
- 因刻意包含边界等待，这是“临期场景压力对照”，不是自然生产流量，也不能将结果直接外推为常规请求成功率。
- 配置保留原.env参数：TTL30秒、余量3秒、批量5、连接/读取静态超时3秒、max_retries=4、动态超时开启、主源预筛。测试进程仅强制always。
- 每次调用附加20秒实验预算；每组150秒网络预算；每组最多6次采购，总上限48次。
- HTTP尝试记录剩余本地TTL、连接/读取预算、结果、耗时和局部代理编号，不记录IP或密钥。
- 本轮约548.08秒，实际33次采购、交付165个IP，未消耗到总上限；只有A第1组触发单组采购上限。

### 临期场景与复用分支

双方各8次刻意临期调用均最终成功：A临期调用P50/P95为4.3705/7.6443秒，B为2.4722/4.8684秒。

A第1组两次临期尝试，剩余TTL约1.243秒、预算6秒，均读取超时，之后换IP恢复。其他A组也有临期尝试成功。因此“预算不足”是风险，并不等于即将请求必然失败；当前供应商真实租期、TCP已有连接行为仍未被该实验直接测定。

B共14次选取扫描发现并过滤预算不足的出口（包括同次回源前的重复检查，不是14个唯一IP）。B保留了3次正常hold复用，真网没有触发hold_rejected。因此本次真网支持的是“领取资格过滤”实际生效；“临期软失败拒绝复用”的正确性目前仅有离线证据，不能标成真网已覆盖。

各组结束时在飞占用与代理管理器均归零，没有隐式直连。整个实验前后正式源码指纹相同。

## 正式实现前需要处理的边界

1. 将剩余TTL与请求预算以明确接口从传输层传入池，不将本次实验的私有方法复制及实例覆盖直接搬进产品。
2. 无适配出口时只合并一次有效回源；供应商重复交付相同临期IP需避免重复采购，同时保留旧IP给更短预算请求。
3. 大响应接口read_timeout可能接近或超过整个短效租期。若机械要求“连接＋读取静态超时”全部能放入TTL，可能让原本实际响应很快的大接口永远没有合格代理。该场景本轮没有真网验证，不能直接全局启用。
4. 连接/读取超时不是严格端到端截止，领取到真正发出请求之间也存在时间差；需要在最终派发边界复核，保留既有总预算限制。
5. 下一轮验证应针对性覆盖真实hold拒绝，并用相同业务量确认重复交付下的采购成本；样本需要覆盖不同时间窗。本轮未证明统计显著性或交易时段效果。

建议：候选方向值得实现和进一步验证；目前保留隔离候选及证据，正式运行策略不在这次实验中改动。
